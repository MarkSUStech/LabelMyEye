## 2. 连接服务器

打开 **Git Bash**（Windows 推荐，自带 ssh/scp），把私钥复制到临时目录并收紧权限：

```bash
cp "C:\Users\mark0\Desktop\01_School_学校资料\Imed\服务器\student" /tmp/srv_key
chmod 600 /tmp/srv_key
```

一条命令连接并执行远程命令（`-p` 是端口，别和 scp 搞混）：

```bash
ssh -i /tmp/srv_key -p 10080 student@10.16.9.162 "hostname"
```

第一次连会问 `Are you sure you want to continue connecting?`，输 `yes`。
看到服务器回显主机名（如 `admin.cluster.local`）就通了。

> **以后所有"在服务器上干活"的命令**，都是这个模式：
> `ssh -i /tmp/srv_key -p 10080 student@10.16.9.162 "你的命令"` —— 引号里的内容在服务器执行。

## 3. 第一次登录：环境探查

一次 SSH 把该看的都看了（重点看注释）：

```bash
ssh -i /tmp/srv_key -p 10080 student@10.16.9.162 "
hostname                                       # 主机名，确认连到了哪台
echo ---GPU---
nvidia-smi --query-gpu=index,name,memory.total,memory.used --format=csv
                                                # 有几张卡、型号、显存、谁在用
echo ---DISK---
df -h ~ | tail -1                              # 家目录剩余空间（模型权重动辄几十G）
echo ---PY---
python3 --version; which python3               # 系统 Python 版本和位置
echo ---NET---
curl -sL -m 10 -o /dev/null -w 'hf-mirror: %{http_code}\n' https://hf-mirror.com
curl -sL -m 10 -o /dev/null -w 'github: %{http_code}\n'    https://github.com
curl -sL -m 10 -o /dev/null -w 'pypi: %{http_code}\n'      https://pypi.org/simple/
curl -sL -m 10 -o /dev/null -w 'tuna: %{http_code}\n'      https://pypi.tuna.tsinghua.edu.cn/simple/
"
```

**探查结果怎么读**（组里这台 Titan 机器的实际情况）：

| 检查项 | 结果 | 对决策的意义 |
|--------|------|--------------|
| GPU | 4× TITAN RTX 24GB，基本空闲 | 单卡 24GB 够跑大部分分割模型；选一张 `内存.used` 最小的 |
| 磁盘 | `/amax` 剩 255G | 10GB 级权重放得下，但注意只用了 86%，别塞满 |
| Python | 3.9.12（conda 环境） | 不动系统环境！自己建 venv（见第 6 节） |
| hf-mirror.com | ✅ 200 | **HuggingFace 被墙，但 hf-mirror 镜像可用** —— 下权重全靠它 |
| github.com | ✅ 200 | git clone 可以 |
| pypi / tuna | ✅ 200 | pip 装包可以，用 tuna 镜像更快 |

> 💡 **网络经验**：国内网络环境下，`huggingface.co`、`dl.fbaipublicfiles.com`、
> `drive.google.com`、`raw.githubusercontent.com` 大概率不通；
> `github.com`、`hf-mirror.com`、`pypi.tuna.tsinghua.edu.cn` 通常可达。
> **选模型先看权重放在哪**——放 HF 的有救（走镜像），只放 Google Drive 的基本没戏。

## 4. 建工作区（安全规矩）

共享服务器上**所有东西都放进一个属于自己的目录**，不碰别人的任何文件：

```bash
ssh -i /tmp/srv_key -p 10080 student@10.16.9.162 "
mkdir -p ~/labelmyeye_bench && cd ~/labelmyeye_bench
git clone --depth 1 https://github.com/AIM-Research-Lab/Medical-SAM3.git
ls Medical-SAM3
"
```

- `--depth 1` 只拉最新版本，省时间省空间
- 工作区结构约定（后面每一步都往里放）：

```
~/labelmyeye_bench/
├── Medical-SAM3/     # 模型代码（git clone）
├── weights/          # 模型权重
├── venv/             # 专属 Python 环境
├── images/           # 上传的待处理数据
├── out/              # 推理输出
├── run_bench.py      # 自己写的推理脚本
└── bench.log         # 运行日志
```

## 5. 下载代码和模型权重

### 5.1 权重在哪找

| 模型 | 权重位置 | 服务器可达性 |
|------|----------|--------------|
| Medical-SAM3 | HF: `Chongcong/Medical-SAM3`（非 gated）| ✅ 走 hf-mirror |
| MedSAM2 | HF: `wanglab/MedSAM2`（非 gated）| ✅ 走 hf-mirror |
| SAM ViT-H/L/B | HF: `ybelkada/segment-anything` | ✅ 走 hf-mirror |
| MobileSAM | GitHub: ChaoningZhang/MobileSAM | ✅ |
| MedSAM3 (Joey-S-Liu) | HF: `lal-Joey/MedSAM3_v1`（LoRA）但**底座 facebook/sam3 是 gated** | ❌ 需向 Meta 申请 |
| MedCLIP-SAMv2 | **只在 Google Drive** | ❌ 服务器/校内均不通 |

**通用下载公式**（HF 模型 → hf-mirror 直链）：

```
https://hf-mirror.com/<组织>/<模型名>/resolve/main/<文件名>
```

例：`https://hf-mirror.com/Chongcong/Medical-SAM3/resolve/main/checkpoint_2D.pt`

### 5.2 下大文件必须用 nohup 后台（关键！）

10GB 的权重直接在前台下，SSH 一断线就前功尽弃。**一律 nohup**：

```bash
ssh -i /tmp/srv_key -p 10080 student@10.16.9.162 "
cd ~/labelmyeye_bench && mkdir -p weights
nohup curl -sL -o weights/checkpoint_2D.pt \
  'https://hf-mirror.com/Chongcong/Medical-SAM3/resolve/main/checkpoint_2D.pt' \
  > dl.log 2>&1 &
echo \"下载已启动 pid=\$!\"
"
```

查进度（`$5/1e9` 把字节数换算成 GB）：

```bash
ssh -i /tmp/srv_key -p 10080 student@10.16.9.162 \
  "ls -la ~/labelmyeye_bench/weights/ | tail -1 | awk '{printf \"%.1f GB\n\", \$5/1e9}'"
```

> 💡 HF 查文件列表（确认文件名/是否 gated）：浏览器开
> `https://hf-mirror.com/api/models/<组织>/<模型名>`，看 `siblings` 和 `gated` 字段。
> `gated: manual` = 要向作者申请权限，匿名下不了。

## 6. 配 Python 环境

**绝不直接 pip 装进服务器的 conda 环境**（会污染别人的环境）。在自己的工作区建 venv：

```bash
ssh -i /tmp/srv_key -p 10080 student@10.16.9.162 "
cd ~/labelmyeye_bench
python3 -m venv venv
nohup bash -c '
  source venv/bin/activate
  pip install -q --upgrade pip -i https://pypi.tuna.tsinghua.edu.cn/simple
  pip install -q torch torchvision -i https://pypi.tuna.tsinghua.edu.cn/simple
  pip install -q -e Medical-SAM3 -i https://pypi.tuna.tsinghua.edu.cn/simple
  echo SETUP_DONE > setup_status.txt
' > setup.log 2>&1 &
echo \"安装已启动 pid=\$!\"
"
```

要点：
- 全程 nohup + 最后一句 `echo SETUP_DONE > setup_status.txt` 做**完成标记**
- 查是否装完：`cat ~/labelmyeye_bench/setup_status.txt`（存在即完成）
- 装完后还可能缺零散包（见 [踩坑记录](#11踩坑记录遇到报错先查这里)），缺啥补啥

## 7. 上传自己的数据

`scp` 的 `-P` 是**大写**（端口）——和 ssh 的小写 `-p` 不同，最容易犯的错：

```bash
# 先在服务器建目录
ssh -i /tmp/srv_key -p 10080 student@10.16.9.162 "mkdir -p ~/labelmyeye_bench/images"
# 再上传（通配符一批传）
scp -i /tmp/srv_key -P 10080 scripts/calibration_data/*.png \
    student@10.16.9.162:~/labelmyeye_bench/images/
```

验证数量：

```bash
ssh -i /tmp/srv_key -p 10080 student@10.16.9.162 "ls ~/labelmyeye_bench/images | wc -l"
```

> 实验做完如不再需要，删掉 `rm -rf ~/labelmyeye_bench/images`。

## 8. 写推理脚本

读模型仓库的推理接口（本地 clone 一份读更方便），围绕它写一个**批量 runner**。
本例（Medical-SAM3）的核心 API 只有三句：

```python
sam3 = SAM3Model(confidence_threshold=0.1, device="cuda",
                 checkpoint_path="weights/checkpoint_2D.pt")
sam3.load_model()                              # 加载 10GB 权重（慢，只做一次）
state = sam3.encode_image(image_np)            # 每张图编码一次
mask = sam3.predict_text(state, "optic disc")  # 文本提示 → 二值 mask
```

完整可用的 runner 已在仓库：[`scripts/server_run_bench.py`](../scripts/server_run_bench.py)。
设计要点（写任何模型的 runner 都适用）：

1. **每张图 encode 一次**，多个提示词复用同一个 state（编码是大头）
2. **每个结构给 2~3 个候选提示词**（如视盘：`optic disc` / `optic nerve head` / `optic nerve`），
   按 `get_confidence()` 择优——你不知道哪个词模型认识
3. mask 尺寸和原图不一致时要 `resize_mask(mask, (H, W))` 还原
4. 输出文件名用约定格式 `<图名>__<标签>.png`（255=前景），
   这样拉回本地后 `benchmark_models.py` 能自动计分
5. 已处理过的跳过（`if os.path.isfile(out_path): continue`）——中断重跑不浪费时间
6. 上游代码有 bug 是常态（本例 `SAM3_ROOT` 未定义），学会用 ssh 里的 python 内联打补丁

## 9. 提交作业并监控

**规则：长任务一律 nohup 后台**，选一张空闲卡（`CUDA_VISIBLE_DEVICES` 从探查结果里挑）：

```bash
ssh -i /tmp/srv_key -p 10080 student@10.16.9.162 "
cd ~/labelmyeye_bench
nohup bash -c 'source venv/bin/activate && CUDA_VISIBLE_DEVICES=0 python run_bench.py' \
  > bench.log 2>&1 &
echo pid=\$!
"
```

监控三板斗（过几分钟来一眼）：

```bash
ssh -i /tmp/srv_key -p 10080 student@10.16.9.162 "
tail -20 ~/labelmyeye_bench/bench.log            # 看日志尾巴
nvidia-smi --query-gpu=index,memory.used --format=csv,noheader   # 看卡
"
```

- 日志在推进 = 在跑；GPU 显存涨了几 GB = 真的在 GPU 上算
- 报错就改，改完重跑（runner 里的跳过逻辑保证已完成的图不会重算）
- 任务结束的标志：日志出现收尾信息、GPU 显存回落

## 11. 踩坑记录（遇到报错先查这里）

本次 Medical-SAM3 部署实际撞到的每一个错，按出现顺序：

| 报错 | 原因 | 解法 |
|------|------|------|
| `No module named 'einops'` | 仓库 requirements 不全，缺零散包 | `pip install einops`（缺啥装啥，常见还有 `pycocotools` `psutil` `scikit-learn` `scikit-image`） |
| `Failed to build 'av'` | 视频解码包要编译，静态图任务用不到 | **跳过不装**，别让它挡住其他包 |
| `NameError: name 'SAM3_ROOT' is not defined` | **上游代码 bug**（用了未定义变量） | ssh 里用 python 内联脚本给对方文件打补丁（在 import 区插入 `SAM3_ROOT = Path(__file__).resolve().parent.parent`） |
| `Can't open file 'run_bench.py'` | scp 静默失败/路径不对 | 单独重传，传完 `ls` 确认再跑 |
| pip 装到一半 SSH 断线 | 前台跑被断连杀掉 | 所有长命令 nohup 后台 + 完成标记文件 |
| `gated: manual`（HF API 查模型时） | 模型作者开了权限审批 | 要么申请权限（等审批），要么找非 gated 的替代模型 |

**通用排查心法**：报错 → 去 `bench.log` 看最后 20 行 → 大部分是
①缺包（pip 补）②上游代码 bug（打补丁）③路径/文件名不对（ls 确认）。
